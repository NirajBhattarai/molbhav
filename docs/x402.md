# Paying deals with x402 on Hedera

When a buyer agrees a price, they can pay it in **testnet USDC** from the **Magic Hedera wallet** they
got at sign-up. Payment uses [x402](https://github.com/x402-foundation/x402) (v2, the `exact` scheme
on `hedera:testnet`): the stall's deal is an HTTP resource that answers `402 Payment Required`, the
buyer signs a USDC transfer, and a **facilitator** verifies it, pays the network fee and submits it.
The settled Hedera transaction is the proof of payment, linked on HashScan.

"I've paid another way" stays for cash and UPI.

## The flow

```
Buyer's phone                      Molbhav (resource server)                 Facilitator          Hedera
     │  GET  /api/bargains/{id}/{stall}/pay                                       │                  │
     │ ─────────────────────────────▶ deal agreed? price ₹176 → 2.00 USDC          │                  │
     │                                payTo = stall's ENS Hedera address           │                  │
     │                                        → mirror node → 0.0.11328762        │                  │
     │                                feePayer ← /supported ─────────────────────▶│                  │
     │ ◀── 402, PAYMENT-REQUIRED ──── accepts: [{ exact, hedera:testnet,           │                  │
     │                                  asset 0.0.429274, amount 2000000,          │                  │
     │                                  payTo 0.0.11328762, extra.feePayer }]       │                  │
     │  Magic signs a TransferTransaction: buyer −2 USDC, stall +2 USDC,           │                  │
     │  transaction id on feePayer (so the buyer needs no HBAR for fees)           │                  │
     │  POST, PAYMENT-SIGNATURE ─────▶ same requirements as asked? ──── /verify ──▶│                  │
     │                                                               ── /settle ──▶│ adds its signature,
     │                                                                             │ submits ────────▶│
     │                                offer → paid, paid_tx = 0.0.9185802@…  ◀─────│◀── receipt ──────│
     │ ◀── 200, PAYMENT-RESPONSE ──── HashScan link                                │                  │
```

- **Where the stall is paid** comes from its **ENS name** (`<label>.molbhav.eth`, ENSIP-11 coin type
  `2147483944` = Hedera testnet), turned into a Hedera account id by the mirror node. A stall without
  a live ENS name falls back to its owner's wallet. See [ens.md](ens.md).
- **Price**: the agreed rupee price at `X402_INR_PER_USD` (default 88), rounded up to USDC's 6 decimals
  so the stall never gets less.
- **The server never sees a key.** Magic signs in the browser; the server checks the signed
  requirements match what it asked, then the facilitator checks the transfer and the signature.

## Setup

| Env                          | Default                        |                                                           |
| ---------------------------- | ------------------------------ | --------------------------------------------------------- |
| `X402_FACILITATOR_URL`       | `https://x402.org/facilitator` | Blocky402 also works: `https://api.testnet.blocky402.com` |
| `X402_INR_PER_USD`           | `88`                           | Rupees per dollar                                         |
| `NEXT_PUBLIC_HEDERA_NETWORK` | `testnet`                      | Shared with the Magic wallet                              |

**The buyer's wallet** needs testnet USDC (token `0.0.429274`):

1. Open the profile to see the Hedera wallet address.
2. Get testnet USDC from [faucet.circle.com](https://faucet.circle.com) (pick Hedera testnet). If the
   account doesn't auto-associate tokens, associate USDC first (HashPack or the Hedera portal).

**The stall's account** must be able to receive USDC: either associated with `0.0.429274` or with
free automatic association slots. Soyeb's `0.0.11328762` has unlimited automatic associations.

## Errors the buyer may see

| Facilitator says                                                                            | Buyer sees                                                     |
| ------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| `invalid_exact_hedera_payload_preflight_failed`, insufficient balance, token not associated | Needs more testnet USDC (faucet.circle.com)                    |
| `invalid_exact_hedera_payload_signature_invalid`                                            | The wallet's signature didn't check out                        |
| anything else                                                                               | The payment didn't go through (details in the browser console) |
